# PROF.STAFF

Демонстрационное приложение для учёта и бронирования оборудования студобъединений.

## Маршруты

- `/#/` — выбор одного из четырёх интерфейсов;
- `/#/miniapp/activist` — мобильный интерфейс активиста;
- `/#/miniapp/admin` — мобильный интерфейс администратора;
- `/#/desktop/activist` — настольный интерфейс активиста;
- `/#/desktop/admin` — настольный интерфейс администратора.

## Локальный запуск через Docker

Проверка готовой сборки:

```powershell
docker compose up --build -d
```

Адрес: http://localhost:8080/ .

Режим разработки (отдельный файл конфигурации):

```powershell
docker compose -f compose.dev.yaml up
```

Адрес: http://localhost:5173/ .

Проверка из контейнера без установки Node.js на компьютер:

```powershell
docker run --rm -v "${PWD}:/app" -w /app node:22-alpine sh -c "npm install --no-audit --no-fund && npm run typecheck && npm test && npm run build"
```

## GitHub Pages

1. Поместить файлы в репозиторий `PROF.STAFF`.
2. В `Settings → Pages → Build and deployment → Source` выбрать `GitHub Actions`.
3. Отправить изменения в `main`: опубликованный сайт будет по адресу `https://<владелец>.github.io/PROF.STAFF/`.
4. Отправка в `dev` выполняет проверки и создаёт артефакт сборки без публикации.

## Демонстрационный сценарий

1. В интерфейсе активиста выбрать оборудование и даты, отправить заявку.
2. Переключиться в интерфейс администратора и согласовать её.
3. Открыть заявку по номеру или QR-коду.
4. Подтвердить выдачу отдельных единиц сканированием QR-кодов или вводом номера.
5. Провести возврат. При повреждении/некомплекте единица получает статус проверки.
6. Проверить актуальные статусы и историю операций.

На странице заявок имеется пример просрочки. Кнопка «Сбросить демо» восстанавливает исходные данные.

## Ограничения демонстрации

- Приложение работает без сервера и без Telegram. Данные хранятся в `localStorage` **только текущего браузера**.
- Роли доступны по прямым ссылкам и не имеют серверной авторизации. Реальные персональные данные использовать нельзя.
- QR-коды содержат только идентификаторы. Для сканирования камерой браузеру нужен защищённый контекст: GitHub Pages через HTTPS или локальный `localhost`.
- Уведомления представлены текущими статусами и предупреждениями внутри приложения, сообщения в Telegram не отправляются.
- Оборудование и заявки демонстрационные, не подключены к реальному учёту ПРОФа.

Исходная постановка кейса: «Система учёта и бронирования оборудования студобъединений».
